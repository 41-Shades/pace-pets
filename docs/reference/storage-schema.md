# Storage Schema

Status: reference.

Pace Pets stores durable history, safe refresh status, and local dashboard audio
preference in `chrome.storage.local`. The latest safe refresh status is stored
separately so the dashboard can show recent collection outcomes even when
history is unchanged.

## Local Preferences

The toolbar badge usage window is stored in `chrome.storage.local` under the generated badge-window preference key so the normal background toolbar badge and badge-view context menu share the same local preference. Dashboard pages store their selected usage window in page-scoped `sessionStorage`; new dashboard pages seed from the stored badge preference, then keep their own selection independent of badge preference changes and other dashboard pages. A `Brake hard!` toolbar badge attention override can temporarily display the critical window label without changing the stored preference or dashboard page selections. Supported values, labels, and durations are listed in the generated section above from `collector/extension/usage-windows.js`.

The dashboard theme is stored in extension-page `localStorage` under `codex-usage-theme`. The dashboard motion preference is stored in extension-page `localStorage` under `pace-pets-dashboard-motion`; its storage events immediately update motion state and stop or restore effects in every other open dashboard page. The dashboard audio preference is stored in `chrome.storage.local` under `pace-pets-dashboard-audio` and records only whether audio is enabled plus the local volume value. Browser playback readiness is not stored; dashboard startup tries to restore it when audio is enabled, but Chrome can still require a fresh dashboard-page gesture after reload before audio can play. These preferences are not usage history and do not contain account identifiers.

Audio preference storage changes update every open dashboard page. Playback
readiness remains page-local, so an externally enabled page does not bypass
Chrome's user-gesture requirement.

Local developer display overrides can be stored when running the unpacked extension. The generated developer-options key and shape above list the supported local override fields. The release packager excludes the dev controls page from Chrome Web Store artifacts; packaged releases use live usage data unless local storage is manually edited by the profile owner.

## Refresh Status

The generated refresh status shape above tracks the latest background check
outcome so the dashboard can distinguish a recent check from the latest stored
chart sample. Successful badge presentations store the selected badge window,
numeric badge pace, and normalized semantic zero-state holds for real supported
windows. Each hold contains only `splat`, `perfectZero`, or `singularity` plus
the matching `resetsAt` identity. Failure status preserves those safe holds so a
failed reset refresh cannot erase the last valid terminal presentation.

Refresh status contains only check metadata and sanitized status text. It must not contain raw upstream responses, auth material, or account identifiers.

The manual refresh cooldown key stores only an ISO timestamp for when the current manual-refresh cooldown ends, so the toolbar context-menu refresh remains cooldown-limited across Manifest V3 service worker restarts. Only deadlines within the canonical 60-second cooldown window are active; expired, invalid, or farther-future values are ignored so clock corrections cannot extend the lock indefinitely.

## Stored Fields

- `id`: sanitized sample identifier, currently based on collection time.
- `collectedAt`: ISO timestamp for when the sample was collected.
- `source`: sanitized collector/source marker.
- `collectorVersion`: sanitized extension version marker.
- `windows.<key>`: normalized usage window for one supported key from the generated supported-window table.
- `remainingPercent`: bounded `0..100` percent remaining, preserving source precision when the source provides remaining usage directly. Current observed WHAM usage-window data reports whole-number `used_percent`, so Pace Pets usually derives this value as `100 - used_percent`.
- `usedPercent`: derived `100 - remainingPercent`, preserving decimal-safe calculation precision.
- `resetsAt`: ISO reset timestamp.
- `windowMinutes`: normalized window duration in minutes.

## Normalization Rules

- Samples without a valid collection timestamp are discarded.
- Windows without valid `remainingPercent`, `resetsAt`, and `windowMinutes` are discarded.
- Windows whose `windowMinutes` do not match the canonical duration for their supported key are discarded.
- Percent values are bounded to `0..100`; display surfaces choose their own rounding. Fractional percent normalization is supported for adapter resilience, but current observed WHAM usage-window precision is whole-percent.
- Positive relative upstream reset durations round up to deterministic minute-boundary timestamps so normalization never moves a reset earlier than its full offset; absolute upstream reset timestamps retain their supplied precision.
- Text markers are whitespace-normalized and capped at 80 characters.
- Stored history is deduped by sample `id`, sorted by `collectedAt`, pruned to retention, compacted for unchanged plateaus, and capped at the newest 500 samples. Samples dated after the current system clock are discarded and repaired from storage so a backward clock correction cannot leave them authoritative.
- History reads and writes share one cross-context Web Lock. A read persists pruning or normalization only when the stored representation changed, and `Clear data` invalidates older refresh generations before removing history and refresh status.

## Forbidden Data

Do not store:

- cookies
- auth headers
- access tokens or session tokens
- raw upstream responses
- raw HTML or page text
- screenshots
- account identifiers
- cross-device or cross-user sync data
